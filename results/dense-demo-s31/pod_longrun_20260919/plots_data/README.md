# Plot data of the long autoregressive run (pod rental of 2026-09-19)

Generated by `../make_plot_data.py` from the mirrored records in `../pod_pull/` (sha256-checked against the pod at the end of the run).
Build, flags, prompts, decode rule: `../POD_LOG.md`. One tick = one token for each of 64 lanes (ring 2^17, 128-bit parameters, two RTX PRO 6000 96 GB).

- `LONG_per_tick.csv` — one row per served tick. `wall_layer_loop_s` is the wall clock of the layer loop (the number to quote);
  `driver_request_to_reply_s` is what the pod-side driver saw; `timer_sum_ms_NOT_A_WALL_CLOCK` is `reqMsPerToken`, a SUM of timers — never quote it
  as a tick time. Pool / device memory after the request, per GPU. Agreement counts are out of `lanes`. `relerr_rms_*` are over the 64 lanes of the tick.
  `max_overflow_in_tick` / `bootstraps_over_512_in_tick` come from the bootstrap flight recorder (TEST key instrument).
- `LONG_per_lane_tick.csv` — one row per lane per tick: raw FHE argmax vs the plaintext model's argmax on the SAME fed sequence (`top1`), the decode
  rule's pick on either side (`pickAgree`), the plaintext top-two margin in logits, `relErrRms` = rms(FHE logits − plaintext logits) / rms(plaintext logits).
- `LONG_per_bootstrap.csv.gz` — one row per bootstrap: the max and rms of the integer overflow of its mod-raise input, the stage that asked for it.
  Rows with `transparent_or_zero_input` = 1 cannot overflow and are excluded from the exceedance statistics.
- `host_memory_per_minute.csv` — host memory of the serving process and used MiB per card, one sample per minute, all arms of the rental (filter on `serve_dir`).
- `LONG_greedy_*` — the 9-tick greedy arm that preceded the run (same binary, greedy argmax decoding, prompt set v3).

Not recorded by this run: ciphertexts, the full FHE logit vectors (so no KL / perplexity difference), GPU power / utilisation.
